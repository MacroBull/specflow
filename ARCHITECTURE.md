# SpecFlow: Deterministic & Progressive Agent Harness
**Version 1.0 | For Claude Code, OpenAI Codex CLI, and GitHub Copilot**

SpecFlow (`sf`) is a lightweight, zero-bloat agent execution harness that bridges the gap between free-form natural language instructions and deterministic software engineering outcomes. Instead of letting coding agents wander in unconstrained loops or forcing developers to write rigid workflow code upfront, SpecFlow introduces a **3-stage lifecycle (`propose` → `lock` → `run`)** backed by **Agent Hook interception**, **Prompt Injection**, and **Progressive Node Formalization (`prompt` → `tool` → `flow`)**.

## 1. Core Design Philosophy

1. **Constraint via Interception, Not Re-implementation**: SpecFlow does not rebuild an IDE or agent runtime. It hooks into existing agent loops (Claude Code hooks, Codex wrapper/MCP, Copilot instructions/hooks) so the host agent *cannot stop* until the active DAG node's exit contracts (`assert`) pass.
2. **Progressive Formalization (`prompt` → `tool`)**: Not every node can or should be written as a deterministic script on day one. Any node can start as a **Profile-Constrained Prompt Node** (`kind: prompt`) running in an isolated or shared context, and later be upgraded in-place via `sf upgrade-node` to a deterministic **Tool Node** (`kind: tool`) without changing the DAG topology or downstream contracts.
3. **Filesystem as the State Machine**: No external databases or background daemons. All specifications, locked DAGs, execution journals, and isolated context snapshots live in `.specflow/` as human-inspectable YAML and JSONL files.
4. **Boundary-Only Verification**: Contracts are validated strictly at node boundaries (`inputs`, `PreToolUse` profile sandbox, and `Stop` exit `assert`).

## 2. Host Adapter Matrix

| Host Agent | Dynamic Prompt Injection (`sf inject`) | Hook / Loop Interception (`sf hook`) | Context Isolation (`isolation`) |
| :--- | :--- | :--- | :--- |
| **Claude Code** | Dynamic block in `.claude/CLAUDE.md` + `UserPromptSubmit` stdout | `.claude/settings.json`: `PreToolUse` (sandbox guard), `PostToolUse` (journal), `Stop` (assertion gate) | `shared`, `context_clean` (`claude -p --system-prompt`), or `worktree` (`git worktree`) |
| **OpenAI Codex CLI** | Dynamic synchronization of `AGENTS.md` | PTY wrapper + local MCP server (`sf mcp-serve`) | Subprocess `codex --approval-mode full-auto -q` per isolated node |
| **GitHub Copilot** | Dynamic synchronization of `.github/copilot-instructions.md` | Copilot Agent MCP bridge + Git `pre-commit` / task gate | Scoped `#file` context attachments |

## 3. Data Model & Directory Layout

```text
.specflow/
├── config.yaml              # Host adapter settings & default profiles
├── specs/
│   └── <feature>.spec.md    # Natural language spec generated by `sf propose`
├── locks/
│   └── <feature>.dag.yaml   # Strongly-typed DAG compiled by `sf lock`
├── flows/                   # Reusable nested subflows (`kind: flow`)
├── tools/                   # Deterministic scripts upgraded from prompt nodes (`kind: tool`)
└── runs/
    └── <run_id>/
        ├── state.json       # Node states (PENDING, RUNNING, RETRY_INJECTED, COMPLETED, FAILED)
        ├── journal.jsonl    # Append-only audit log of transitions & assertion checks
        └── artifacts/       # Strongly-typed intermediate node outputs
```

## 4. Node Kinds & Built-in Standard Library (`std/*`)

- **`atomic`**: Zero-LLM built-in primitives (`std/repo-map`, `std/context-pack`, `std/git-checkpoint`, `std/file-guard`, `std/cmd-exec`, `std/schema-check`, `std/ast-grep`).
- **`prompt`**: Constrained LLM execution governed by an `AgentProfile` (`model`, `isolation`, `allowed_tools`, `writable_paths`, `denied_paths`, `max_turns`).
- **`tool`**: Deterministic CLI/script execution (`cmd`) with optional `fallback_profile`.
- **`flow`**: Composable nested DAG subflows (`std/tdd-red-green`, `std/map-reduce-audit`, `std/safe-migration`).

## 5. CLI Command Reference (`sf`)

- **Core Lifecycle**: `sf propose "<intent>"`, `sf lock <spec.md>`, `sf run <dag.yaml> [--host claudecode|codex|copilot]`
- **Hooks & Injection**: `sf hook pre-tool`, `sf hook post-tool`, `sf hook stop`, `sf inject`
- **State Machine**: `sf status [--graph]`, `sf state reset <node_id> [--hard]`, `sf state override <node_id> --out k=v`, `sf state replay <run_id> --from <node_id>`
- **Diagnostics & Evolution**: `sf inspect <node_id>`, `sf doctor`, `sf env init --host <host>`, `sf upgrade-node <dag.yaml> <node_id>`
